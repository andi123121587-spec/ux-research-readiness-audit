# Contributing

Contributions should preserve the Skill's evidence boundary and designer decision control.

Before opening a change:

1. Explain which research-readiness failure the change addresses.
2. Keep facts, analysis, assumptions, and design decisions visibly separate.
3. Do not add invented users, quotes, findings, or validation results.
4. Add or update a synthetic evaluation case when behavior changes.
5. Run the report validator and document any remaining limitations.

Please keep local Codex state, raw run logs, SQLite files, private research material, and absolute local paths out of commits.
