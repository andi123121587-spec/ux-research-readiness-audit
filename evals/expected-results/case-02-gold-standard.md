# Case 02 Gold Standard｜核心证据缺失

## 测试目的

检查 Skill 是否会：

- 将利益相关者要求与用户证据分开；
- 拒绝把无来源画像、痛点和功能列表当作研究结论；
- 阻止直接进入高保真和开发承诺；
- 不替项目编造访谈、用户画像或流程。

## 可接受结论范围

- 原型探索：仅允许低保真、可抛弃、明确标注为假设的探索；不允许正式高保真承诺；
- 研究主张：`CLAIM_NOT_READY`；
- 三档总评：应为 `NOT_READY`；
- 至少存在一个 BLOCKER。

## Gold Issues

| Gold ID | 应识别的问题 | 建议严重度 |
|---|---|---|
| G02-EVI | 没有一手用户证据 | BLOCKER |
| G02-USR | 目标用户和用户画像没有来源 | BLOCKER/MAJOR |
| G02-JNY | 真实借还、审批、多地点工作流程未知 | BLOCKER |
| G02-FTR | 功能来自管理层要求，不能作为用户需求证明 | MAJOR |
| G02-RSK | 权限、错误成本、丢失、合规和设备环境未知 | BLOCKER/MAJOR |
| G02-VAL | 没有明确原型需要验证的问题 | MAJOR |

## 不应出现

- 自动生成“展品管理员 Persona”并作为事实；
- 自动生成用户痛点或访谈引语；
- 直接推荐最终权限体系；
- 因为管理层需要看板就认定用户需要看板；
- 将二维码效率写成已验证结论。

## 最低补充路径

应优先推荐：

1. 识别真实使用者与利益相关者；
2. 观察或访谈当前工作流程；
3. 获取现有 Excel、借还记录和错误案例；
4. 识别权限、审批、多地点和异常处理；
5. 再用低保真流程原型验证高风险假设。
