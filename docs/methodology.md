# Methodology

The audit starts with evidence, then checks whether analysis connects evidence to a concrete design decision. It uses a nine-dimension minimum package as a coverage map, not as a checklist that automatically creates nine Issues.

The preferred sequence is:

1. Identify project mode and current decision.
2. Separate facts, interpretations, hypotheses, and decisions.
3. Classify conflicts by layer: problem existence, user/scenario scope, trade-off, proposed solution/default, or interaction detail.
4. Establish shared root causes.
5. Apply severity and the counterfactual BLOCKER threshold.
6. Map affected dimensions to a small Issue set.
7. Report exploration, solution, claim, and aggregate states.
8. Give actions, review conditions, and designer decision points.

The method favors useful learning over formal completeness. A mature project with missing public documentation is not automatically treated as research failure, and conflicting evidence can justify multi-path exploration rather than a full stop.
